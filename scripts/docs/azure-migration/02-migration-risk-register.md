# Migration Risk Register

## 1. Authentication Parity
**Risk**: NextAuth relies heavily on Next.js/Vercel server context. Moving business logic to Azure requires strict API token validation or JWT sharing between Vercel and Azure.
**Mitigation**: Implement strict JWT validation at the Azure API Gateway layer and ensure token signing secrets are shared securely via Azure Key Vault.

## 2. Database Concurrency during Cutover
**Risk**: If Next.js Server Actions and Azure Container Apps both write to the database simultaneously during wave migration, it could cause race conditions or corrupt financial totals.
**Mitigation**: Use strictly controlled feature flags for API rewrites. Isolate entire modules (e.g. Procurement) to route exclusively to Azure once cutover.

## 3. File Upload Proxy Bottleneck
**Risk**: Proxying large file uploads through Vercel to Azure Blob Storage might exceed Vercel's 4.5MB payload limit on serverless functions.
**Mitigation**: Implement direct-to-storage uploads via Pre-Signed URLs generated by the Azure backend.

## 4. Double-Entry Accounting Synchronization
**Risk**: If a network failure occurs between the Vercel Frontend and Azure Backend during a financial transaction approval, the UI might show failure while the backend processes it.
**Mitigation**: Enforce Idempotency Keys on all financial write operations to Azure.
